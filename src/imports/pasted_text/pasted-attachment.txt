Design a polished web-based educational coding game called **Codepoly**.

Codepoly is a learning product for complete beginners and introductory computer science students. It combines a colorful board-game experience inspired by the energy and accessibility of Mario Party and Monopoly with coding exercises, debugging challenges, multiple-choice questions, output prediction, logic questions, and short programming tasks.

The product should feel like a **real game first**, while still being clean enough for universities and professors to use in classrooms.

## PRIMARY DESIGN GOAL

Create the **main gameplay screen** for Codepoly.

The entire board must be visible without requiring scrolling.

The board should surround a central gameplay area.

The page should feel polished, intentional, playful, and premium.

Do NOT make this look like:

* a generic SaaS dashboard
* an AI-generated landing page
* a crypto product
* a children's learning app
* a copy of Monopoly
* a copy of LeetCode
* an overly futuristic gaming interface

Avoid excessive gradients, glassmorphism, glowing borders, random floating cards, excessive shadows, excessive rounded rectangles, unnecessary badges, giant empty spaces, or decorative elements without purpose.

Every element must have a clear functional reason to exist.

The UI must have strong visual hierarchy and consistent spacing.

---

# CANVAS

Design for desktop web first.

Primary frame:
**1440 × 900**

The entire game experience should fit inside this viewport.

No page scrolling during gameplay.

Use responsive principles so the board could later adapt to smaller laptop sizes.

---

# GENERAL VISUAL DIRECTION

Style:
**Mario Party energy + modern educational product + premium coding interface**

The board can be colorful and expressive.

The center coding interface should become calmer and cleaner so users can concentrate.

Use a light interface overall.

Background:
soft warm off-white or very light neutral.

Do not use pure white everywhere.

Use subtle texture or very soft background shapes only if needed.

Typography:
Use a modern, friendly sans-serif.

Suggested direction:
Inter, Geist, Manrope, or similar.

Headings should feel friendly but not childish.

Code must use a proper monospaced font.

It should occupy approximately:

680–720px height

# FINAL COMPOSITION PRIORITY

When someone sees the screen, their eyes should naturally move in this order:

1. Game board
2. Current challenge
3. Their player position
4. What they need to do next
5. Reward / progress
6. Other players

The interface should answer these questions instantly:

Where am I?

What challenge am I doing?

What do I need to do?

What happens if I succeed?

Whose turn is it?

How am I performing?
